# 错题登记表 · 字段清单（照此填写平台数据表）

表名建议：`mistake_log`（或直接叫「错题登记」）
一行 = 一个学生在一道题上的一次记录。**不设唯一约束**，同一题错多次就多行。

## 一、逐行填写

| 序 | 字段名 | 字段描述（填在描述栏） | 类型 | 长度 | 必须 | 唯一 | 启用 | 默认值 |
|---|---|---|---|---|---|---|---|---|
| 2 | `student_id` | 学号，如 2023010234 | String | 短文本 | ✅ | ❌ **（务必取消）** | ✅ | 留空 |
| 3 | `exercise_id` | 平台题号，如 sql.q13 | String | 短文本 | ✅ | ❌ | ✅ | 留空 |
| 4 | `error_code` | 错因码 DF-/SQ-/BP-；通过写 PASS | String | 短文本 | ✅ | ❌ | ✅ | 留空 |
| 5 | `note` | 一句话备注，可空 | String | 短文本 | ❌ | ❌ | ✅ | 留空 |
| 6 | `recorded_at` | 记录时间 YYYY-MM-DD HH:MM | String / 日期时间 | 短文本 | ✅ | ❌ | ✅ | 留空（由助教写） |
| 7 | `class_id` | 班级，如 信管2301，可空 | String | 短文本 | ❌ | ❌ | ✅ | 留空 |

> 第 1 行（序号 1 的 `--`）是平台自动生成的主键，不要动。

## 二、三处必须改

1. `student_id` 的「是否唯一」**取消勾选**——一个学生会错很多题，勾了唯一，第二条记录就写不进去。
2. `exercie_id` → `exercise_id`（拼写错误，趁没数据改掉）。
3. 新增 `recorded_at`——没有时间，教师没法区分"本周"和"三周前"，聚合会把三次课混成一份。

## 三、题号取值表（写进表里必须是这些值）

| 实验 | exercise_id 取值 |
|---|---|
| 实验一 数据流图 | `dfd.quiz.1`–`dfd.quiz.5`、`dfd.draw.lib`、`dfd.draw.course`、`dfd.find.f1`–`f4` |
| 实验二 SQL | `sql.q1`–`sql.q17` |
| 实验三 业务流程 | `bpm.sym.unit` / `proc` / `doc` / `store` / `ext`、`bpm.sort.borrow`、`bpm.sort.leave`、`bpm.blank.b1`–`b4`、`bpm.draw` |

## 四、错因码取值（对应知识库 error_patterns）

- `DF-01`–`DF-08`：数据流图类
- `SQ-01`–`SQ-08`：SQL 类
- `BP-01`–`BP-06`：业务流程类
- `PASS`：核对通过（用于算正确率）

## 五、示例数据（填表后自测用，测完删掉）

```json
{ "student_id": "2023010234", "exercise_id": "sql.q13", "error_code": "SQ-03", "note": "子查询用了 = 而不是 IN", "recorded_at": "2026-10-18 15:32", "class_id": "信管2301" }
{ "student_id": "2023010234", "exercise_id": "sql.q14", "error_code": "PASS", "note": "", "recorded_at": "2026-10-18 15:38", "class_id": "信管2301" }
```

## 六、验收三问（教师模式）

1. 「班级现在什么情况」→ 应报时间范围、样本量、错因 Top 3（带实体 ID）、错题 Top 5、10 分钟补讲设计。
2. 「看看 2023010234」→ 应给该生薄弱点 + 具体该练的题号。
3. 清空表后再问 → 必须回答"表里还没有记录"，**不能编数字**。
